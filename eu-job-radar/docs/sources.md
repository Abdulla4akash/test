## API access and actual response shapes

| ATS | Public documentation checked 2026-09-25 | Result |
|---|---|---|
| Greenhouse | [Job Board API](https://docs.greenhouse.io/job-board.html) | Readable; old developers.greenhouse.io URL redirects here. Published-board GET requires no authentication. |
| Lever | [Postings API](https://github.com/lever/postings-api) | Readable; unfiltered JSON list of published postings, no authentication. EU account host is documented but was not live-tested in this run. |
| Ashby | [Public job posting API](https://developers.ashbyhq.com/docs/public-job-posting-api) | Readable; published-board GET, no authentication. Documentation and live JSON differ in secondary-address nesting; both are supported. |

Live responses were compared with the adapters, and **all 33 retained cached
payloads were replayed through the revised parsers**, offline: complete,
zero quarantined items. No captured response was copied into a test or Git.

- **Greenhouse:** object with `jobs[]`, numeric `id`, `title`,
  `location.name`, `absolute_url`, `updated_at`, `first_published`.
  Additional fields such as `metadata`, `application_deadline`, and
  `data_compliance` are not needed for the current collected record. A
  `meta.total` shortfall, where present, remains partial. No `content=true`
  or per-job detail requests were made to this API.
- **Lever:** JSON list with `id`, `text`, `hostedUrl`, `categories.location`,
  `categories.allLocations`, `categories.commitment`, `workplaceType` and
  `createdAt` in milliseconds. Descriptions are included by the API even
  though the parsed records discard them. Unrepresentable timestamps now
  become unknown rather than aborting a board read.
- **Ashby:** `jobs[]` with stable `id`, `title`, `location`,
  `secondaryLocations`, `isListed`, `isRemote`, `workplaceType`,
  `employmentType`, `publishedAt`, `jobUrl`, descriptions and structured
  addresses. Live secondary addresses use `address.postalAddress`, whereas
  the docs also describe flat `address` objects. Both are read, keeping
  each location together with its own country/region rather than losing
  secondary country evidence. Unlisted jobs are skipped.

Collection now has a **20,000,000-byte bound**, including decompressed
responses. The 5 MB default rejected OpenAI (13,765,315 decompressed bytes)
and Palantir (6,240,046 bytes); their targeted retries succeeded. Page checks
retain the 5 MB default. Tests exercise a synthetic 6 MB successful board
and an over-20 MB compressed response that is refused. This remains a
finite limit: a larger future board will fail visibly and cannot mark jobs
missing. The user-agent's project link was corrected to this repository;
the shared HTTP transport/robots policy and eu-phd-radar were otherwise
left alone.

## Screening review and bugs fixed

The requested `inbox` and `inbox --view outside` ran on the collected data.
`inbox --view check` initially failed because the view did not exist; it is
now implemented and all three commands ran successfully after the fixes.

For the initial 6,090 records, the original rules produced 476 relevant,
85 check and 5,529 outside. A deterministic sample of **60 per bin** was
reviewed (evenly spaced through the inbox's existing sort, index
`floor(i * bin_length / 60)`, for `i = 0..59`). The same samples were
re-screened after fixes, with the same default preferences:

| Original sample | Finding under title/location rules | After fixes |
|---|---|---|
| 60 relevant | 2 sales/value-engineering titles admitted (2/60, 3.3% of sampled matches) | Both outside; 58 remain relevant. |
| 60 outside | 2 software roles missed: core developer, microservices engineer (2/60, 3.3% of sampled exclusions) | Both relevant; 58 remain outside. |
| 60 check | 5 readable outside locations and 3 non-target role functions | 8 now outside; 52 still need checking. |

These are **observed sample error proportions**, not population false-positive
or false-negative rates, independent test-set estimates, or eligibility
judgements. Titles alone cannot settle ambiguous systems/production work.
The final stored inventory has 7,570 postings: **585 relevant, 78 check,
6,907 outside**. Those totals also include the four recovered boards, so
they are not a controlled before/after comparison. Structured-address parser
changes were additionally verified by replaying all cached responses; the
stored inventories are from the two live runs, not another collection.

Rules and regression cases now cover:

- Engineering function versus business area (software engineers on content,
  sales and finance systems); AI customer/value/solutions roles and other
  non-engineering titles cannot pass merely because they contain AI or ML.
- Core developers, microservices engineers and research/ML internships;
  “Member of Technical Staff” does not automatically mean staff seniority.
- Cambridge UK versus Massachusetts or an unqualified Cambridge; Ontario,
  country/state code collisions, slash/comma city lists, Detroit/Washington,
  and remote AMER. GMT/CET/CEST alone are not geographic hiring permission.
  DACH cannot satisfy a UK-only preference just by saying Europe. An unknown
  alternative location stays a check unless an explicit allowed location
  independently matches. Remote EMEA remains a stated-region match.
- Malformed/blank titles and duplicate IDs make inventories partial. The
  ingestion boundary also refuses to mark missing if any items were
  quarantined, even if a caller incorrectly labels the result complete.
- Nested collection guards retain protection; renaming a user table cannot
  evade it. Populated v1 migration preserves applications/tasks and remains
  idempotent; unsupported versions produce a domain error.
- Partial window reports preserve the other endpoint and local metadata;
  old-cycle reports cannot supply new-cycle dates. Announcements require
  quote/source/check date, fixed opening dates cannot be overridden, and
  a tracked old deadline cannot hide a newer official announcement.
- Invalid dates, impossible times, reversed windows and negative budgets,
  deadline horizons or inbox limits are rejected; `--limit 0` returns zero.
  Page checks read the quote's source URL and decode HTML entities; demo
  workspaces cannot make live page checks. Manual application statuses do
  not invent an application date when the user has not recorded applying.

Validation: **174 offline tests pass**, `ruff check .` and
`ruff format --check .` pass, and the offline demo passes **21/21**.
Tests use fictional employers/example.org links and synthetic API shapes.
